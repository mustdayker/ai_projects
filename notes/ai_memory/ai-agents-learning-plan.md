# Учебный план: AI и агенты (адаптирован под middle Data Engineer)

## ПРОТОКОЛ НОВОГО ЧАТА (bootstrap — читать первым!)
- Пользователь создаёт НОВЫЙ ЧАТ НА КАЖДЫЙ ЭТАП внутри проекта «Курс обучения AI» (бывш. Learning & Research; переименован 2026-11-03, защита от переполнения контекста).
- Чат Этапа 0 называется «Этап 0. Фундамент LLM и API». Предположительно чаты следующих этапов будут названы по тому же шаблону.
- В начале учебного чата ассистент ОБЯЗАН: (1) прочитать этот файл; (2) прочитать topic/user-tech-profile.md; (3) сверить раздел «Статус прохождения».
- Стартовая команда пользователя: «Этап N — погнали» (или просто номер этапа). Ассистент начинает с Шага 1 указанного этапа по правилам ниже — без пересогласования формата.
- Если чат — продолжение незакрытого этапа, ассистент продолжает с места из «Статуса прохождения».
- После КАЖДОГО значимого события (шаг выдан, задание разобрано, этап закрыт, выдана шпаргалка) ассистент обновляет «Статус прохождения» в этом файле.
- При закрытии этапа: шпаргалка-конспект md → файл в /mnt/agents/output/ + запись о ней в разделе «Шпаргалки» (краткое резюме содержимого, чтобы в новых чатах было понятно, что пройдено, без чтения самих файлов).

## Договорённости о формате
- Преподавательский стиль: подробно, с нюансами и примерами, на русском.
- Темп: 5–10 часов в неделю (~14–18 недель на весь курс).
- Сквозной проект: RAG-система; text-to-SQL и агент качества данных — мини-упражнения на этапе 7.
- Контур: гибрид — основа локальные модели, сравнение с облачными фронтирными моделями в ключевых точках.
- КРИТИЧНОЕ требование: provider-agnostic архитектура — подключение любого LLM (локальный/облачный), работа в открытом и закрытом контурах. Сквозной принцип: OpenAI-совместимый API + LiteLLM-шлюз, нигде не хардкодим модель.

## ПРАВИЛО НУМЕРАЦИИ (действует всё обучение, с 2026-11-03)
Трёхуровневая адресация «Этап.Шаг.Пункт»:
- Этапы 0–8 (как в плане).
- Шаги внутри этапа: Шаг 1, Шаг 2, …
- Пункты внутри шага: нумеруются ВСЕ блоки подряд (суть, нюансы, грабли, задание, контрольные вопросы).
- Ссылка на место: «Этап 0, Шаг 1, Пункт 2» или кратко «0.1.2». Пользователь переспрашивает, указывая точный адрес.

## Процесс прохождения (финальная версия)
- ЭТАПНЫЙ ЦИКЛ: пользователь пишет номер этапа → начинаем. К следующему этапу НЕ переходим, пока пользователь явно не скажет, что этап закончен. После закрытия этапа — конспект-шпаргалка (markdown-файл).
- Шаг = одно сообщение: суть с нюансами → примеры из практики DE → типичные грабли → задание на свою машину (30–60 мин) → контрольные вопросы. Между шагами двигаемся автоматически.
- Вспомогательные вопросы встраиваются в шаг, сколько угодно.
- Проверка практики: пользователь присылает код и вывод; разбираем вместе.
- Контроль в конце этапа: только разбор артефакта, БЕЗ квиза.
- С этапа 1 ведём «дневник наблюдений» за моделями (model-notes.md, в репозитории пользователя).
- Гибкий темп: «пауза»/«повтори шаг» в любой момент.

## Этапы (финальная версия от 2026-11-02)
0. Фундамент LLM и API (~1 нед.): токены, контекст, system prompt, OpenAI-совместимый API. План шагов: 1) токены; 2) контекстное окно, роли, system prompt; 3) параметры генерации; 4) OpenAI-совместимый API + первый код.
1. Локальный инференс-стек (~2 нед.): Ollama, vLLM, llama.cpp; квантизация (16 GB VRAM); Docker; LiteLLM-шлюз; выбор моделей.
2. CLI и окружение на Windows (~1 нед.): WSL2, OpenCode + локальные модели, AGENTS.md.
3. Агенты изнутри (~2 нед.): агентный цикл, function calling; мини-агент (файлы + SQL к Postgres).
4. RAG с нуля на локальных моделях (~3 нед., ключевой): эмбеддинги (многоязычные), чанкинг, pgvector (HNSW), гибридный поиск (вектор + BM25), реранкинг, оценка качества; MinIO → pgvector, Jupyter.
5. Скиллы (SKILL.md) и MCP (~1–2 нед.): свои скиллы, локальные MCP-серверы (Postgres, filesystem).
6. Spec-driven development (~1 нед.): AGENTS.md, OpenSpec.
7. Мультиагентные системы (~2–3 нед.): оркестратор + воркеры, LangGraph; мини-кейсы DE.
8. Закрытый контур и продакшн (~1–2 нед.): air-gap, безопасность, мониторинг, реестр моделей; финальный проект.
